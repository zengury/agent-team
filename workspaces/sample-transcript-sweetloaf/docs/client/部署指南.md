## 一、部署概览

本文档详细说明如何将SweetLoaf运营管理平台部署到服务器上，让陈老板和店员们可以通过浏览器正常使用。

### 1.1 部署架构

```
┌─────────────┐     ┌──────────────┐     ┌──────────────┐
│  员工手机端  │────▶│              │     │              │
│  (浏览器)    │     │              │     │   SQLite     │
├─────────────┤     │   Flask App  │────▶│   数据库     │
│  老板电脑端  │────▶│  (服务器)    │     │  (本地文件)  │
│  (浏览器)    │     │              │     │              │
├─────────────┤     │              │     └──────────────┘
│  店员电脑端  │────▶│              │
│  (浏览器)    │     └──────────────┘
└─────────────┘
```

**说明：**
- 系统采用B/S架构（浏览器/服务器模式）
- 所有用户通过浏览器访问系统
- 数据存储在服务器的SQLite数据库中
- 部署简单，无需额外安装数据库软件

### 1.2 环境要求

| 组件 | 最低要求 | 推荐配置 |
|:---|:---|:---|
| 操作系统 | Ubuntu 20.04 / CentOS 7 / macOS / Windows Server 2016 | Ubuntu 22.04 LTS |
| Python | 3.8+ | 3.10+ |
| 内存 | 512MB | 2GB+ |
| 磁盘 | 1GB可用空间 | 10GB+（用于存储数据） |
| 网络 | 固定IP或域名 | 固定公网IP + 域名 |

## 二、快速部署（5分钟搞定）

### 2.1 获取项目代码

```bash
# 方式一：从Git仓库克隆（推荐）
git clone https://github.com/your-org/sweetloaf-platform.git
cd sweetloaf-platform

# 方式二：直接下载压缩包并解压
# 将压缩包上传到服务器后：
unzip sweetloaf-platform.zip
cd sweetloaf-platform
```

### 2.2 安装Python和依赖

```bash
# 检查Python版本
python3 --version
# 确认输出为 Python 3.8.x 或更高版本

# 如果Python版本过低，需要升级（以Ubuntu为例）：
sudo apt update
sudo apt install python3.10 python3.10-venv python3-pip -y

# 创建虚拟环境（强烈推荐）
python3 -m venv venv

# 激活虚拟环境
# Linux/macOS:
source venv/bin/activate
# Windows:
# venv\Scripts\activate

# 安装项目依赖
pip install -r src/requirements.txt
```

**依赖清单（requirements.txt内容）：**
```
Flask==2.3.3
Flask-SQLAlchemy==3.0.5
Flask-CORS==4.0.0
gunicorn==21.2.0
python-dotenv==1.0.0
```

### 2.3 配置环境变量

```bash
# 创建环境变量文件
cp .env.example .env

# 编辑.env文件，根据实际情况修改
nano .env
```

**.env文件内容示例：**
```bash
# 运行环境：development（开发）或 production（生产）
FLASK_ENV=production

# 安全密钥（务必修改为随机字符串）
SECRET_KEY=sweetloaf-2026-secret-key-change-me

# 数据库路径（默认使用项目根目录下的sweetloaf.db）
DATABASE_URL=sqlite:///sweetloaf.db

# 服务器端口
PORT=5000

# 管理员账号（首次启动时自动创建）
ADMIN_USERNAME=admin
ADMIN_PASSWORD=admin123
```

> ⚠️ **安全提醒：** 生产环境中务必修改 `SECRET_KEY` 和 `ADMIN_PASSWORD`，不要使用默认值！

### 2.4 初始化数据库

```bash
# 确保在项目根目录下
cd /path/to/sweetloaf-platform

# 首次启动会自动创建数据库和表结构
# 也可以手动初始化：
python src/init_db.py
```

### 2.5 启动服务

```bash
# 开发环境测试启动（直接运行）
python src/app.py

# 生产环境启动（使用gunicorn，推荐）
gunicorn -w 4 -b 0.0.0.0:5000 src.app:app
```

**启动参数说明：**
- `-w 4`：启动4个工作进程（根据服务器CPU核心数调整）
- `-b 0.0.0.0:5000`：监听所有网络接口的5000端口
- `src.app:app`：指定Flask应用对象

### 2.6 验证部署

```bash
# 在服务器本地测试
curl http://localhost:5000/
# 应返回：{"status": "ok", "message": "SweetLoaf API is running"}

# 测试API是否正常
curl http://localhost:5000/api/stores
# 应返回包含三家门店信息的JSON数据
```

## 三、生产环境部署（正式上线）

### 3.1 使用systemd管理服务（Linux推荐）

创建systemd服务文件，让系统在后台自动运行，并支持开机自启。

```bash
# 创建服务文件
sudo nano /etc/systemd/system/sweetloaf.service
```

**服务文件内容：**
```ini
[Unit]
Description=SweetLoaf Bakery Management Platform
After=network.target

[Service]
User=www-data
Group=www-data
WorkingDirectory=/opt/sweetloaf-platform
Environment="FLASK_ENV=production"
Environment="SECRET_KEY=your-secure-key-here"
Environment="DATABASE_URL=sqlite:///sweetloaf.db"
ExecStart=/opt/sweetloaf-platform/venv/bin/gunicorn -w 4 -b 0.0.0.0:5000 src.app:app
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
# 重新加载systemd配置
sudo systemctl daemon-reload

# 启动服务
sudo systemctl start sweetloaf

# 设置开机自启
sudo systemctl enable sweetloaf

# 查看服务状态
sudo systemctl status sweetloaf

# 查看实时日志
sudo journalctl -u sweetloaf -f
```

### 3.2 使用Nginx反向代理（推荐）

Nginx可以作为反向代理，提供更好的性能和安全性。

```bash
# 安装Nginx
sudo apt install nginx -y

# 创建Nginx配置文件
sudo nano /etc/nginx/sites-available/sweetloaf
```

**Nginx配置内容：**
```nginx
server {
    listen 80;
    server_name sweetloaf.yourdomain.com;  # 替换为您的域名

    # 将请求转发到Flask应用
    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 静态文件缓存（可选）
    location /static {
        alias /opt/sweetloaf-platform/static;
        expires 30d;
    }

    # 日志配置
    access_log /var/log/nginx/sweetloaf_access.log;
    error_log /var/log/nginx/sweetloaf_error.log;
}
```

```bash
# 启用站点配置
sudo ln -s /etc/nginx/sites-available/sweetloaf /etc/nginx/sites-enabled/

# 测试配置是否正确
sudo nginx -t

# 重启Nginx
sudo systemctl restart nginx
```

### 3.3 配置HTTPS（使用Let's Encrypt免费证书）

```bash
# 安装Certbot
sudo apt install certbot python3-certbot-nginx -y

# 获取并自动配置SSL证书
sudo certbot --nginx -d sweetloaf.yourdomain.com

# 按照提示操作：
# 1. 输入邮箱地址（用于接收续期通知）
# 2. 同意服务条款
# 3. 选择是否将HTTP重定向到HTTPS（建议选择"是"）

# 测试自动续期
sudo certbot renew --dry-run
```

## 四、数据迁移与备份

### 4.1 数据库备份

```bash
# 手动备份数据库
cp /opt/sweetloaf-platform/sweetloaf.db /opt/sweetloaf-platform/backups/sweetloaf_$(date +%Y%m%d_%H%M%S).db

# 创建自动备份脚本
sudo nano /opt/sweetloaf-platform/backup.sh
```

**备份脚本内容：**
```bash
#!/bin/bash
BACKUP_DIR="/opt/sweetloaf-platform/backups"
DB_PATH="/opt/sweetloaf-platform/sweetloaf.db"
RETENTION_DAYS=30

# 创建备份目录
mkdir -p $BACKUP_DIR

# 备份数据库
cp $DB_PATH "$BACKUP_DIR/sweetloaf_$(date +%Y%m%d_%H%M%S).db"

# 删除30天前的旧备份
find $BACKUP_DIR -name "sweetloaf_*.db" -mtime +$RETENTION_DAYS -delete

echo "Backup completed at $(date)"
```

```bash
# 设置执行权限
chmod +x /opt/sweetloaf-platform/backup.sh

# 添加到crontab，每天凌晨3点自动备份
crontab -e
# 添加以下行：
0 3 * * * /opt/sweetloaf-platform/backup.sh >> /var/log/sweetloaf_backup.log 2>&1
```

### 4.2 数据恢复

```bash
# 停止服务
sudo systemctl stop sweetloaf

# 恢复数据库
cp /opt/sweetloaf-platform/backups/sweetloaf_20260515_120000.db /opt/sweetloaf-platform/sweetloaf.db

# 启动服务
sudo systemctl start sweetloaf

# 验证数据是否恢复
curl http://localhost:5000/api/stores
```

## 七、常见部署问题排查

### 问题1：启动时报错 "Address already in use"

```bash
# 查看哪个进程占用了5000端口
sudo lsof -i :5000

# 终止占用进程
sudo kill -9 <PID>

# 或者修改端口号
export PORT=5001
python src/app.py
```

### 问题2：数据库权限错误

```bash
# 确保数据库文件有正确的读写权限
sudo chown www-data:www-data /opt/sweetloaf-platform/sweetloaf.db
sudo chmod 664 /opt/sweetloaf-platform/sweetloaf.db
```

### 问题3：Nginx 502 Bad Gateway

```bash
# 检查Flask应用是否在运行
sudo systemctl status sweetloaf

# 检查Nginx配置是否正确
sudo nginx -t

# 查看Nginx错误日志
tail -f /var/log/nginx/sweetloaf_error.log
```
